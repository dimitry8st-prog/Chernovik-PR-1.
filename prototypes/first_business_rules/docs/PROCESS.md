# Состояния и результаты локального стенда

## Порядок обработки

| Этап | Условие входа | Результат и переход | Остановка / ответственный |
| --- | --- | --- | --- |
| Приём компании | Корректный идентификатор и запись контакта | Сохранить исходные поля, ID, время и результат проверки | Дубль контакта или конфликт ID — отказ без второй записи; оператор стенда |
| Квалификация | Проверенные исходные сведения | `qualified` показывает соответствие ICP; `contact_allowed` — отдельный допуск только к симуляции | Неполный профиль, неподтверждённый источник, истёкшее основание — `REVIEW`; владелец данных |
| Подготовка обращения | Контакт допустим, нет STOP и аварийной остановки | `PREPARED` в локальном outbox; фактической отправки нет | Состояние/правила проверяются при каждом новом действии; оператор |
| Наблюдение результата | Идентифицированный draft и синтетическая квитанция | ACCEPTED, DELIVERED или UNKNOWN записываются раздельно | UNKNOWN — `RECONCILE`, без автоматического повтора; оператор |
| Переписка | Известный контакт и уникальное входящее сообщение | Сначала сохранить письмо, затем проверить предложение классификатора | Неверный формат, недостаточная уверенность, неизвестный факт — `REVIEW`; человек |
| Подготовка передачи | Синтетический подтверждённый интерес с цитатой и текущим допуском | F1-19/F1-09 создают `PREPARED / NOT_DISPATCHED`; диалог на паузе | Ошибка полного контекста — история остаётся, ручной разбор; интегратор |
| Доставка пакета | Совпадают область, handoff ID и хеш | Синтетическая delivery receipt; менеджер ещё не принял | UNKNOWN и отсутствие подтверждения — ожидание в пределах таймера, затем эскалация |
| Принятие менеджером | DELIVERED, правильный получатель, ID/хеш, срок не истёк | Отдельный локальный ACK `MANAGER_ACCEPTED` либо `MANAGER_DECLINED` | Просроченный ACK — эскалация и ручная сверка; руководитель продаж |

## Рубрика ответов

| Категория | Пример фикстуры | Действие |
| --- | --- | --- |
| QUESTION | What is included? | Черновик по утверждённым фактам, ручная проверка; интерес не подтверждён |
| REQUEST_INFO | Please send information. | Подготовка информационного черновика; интерес не подтверждён |
| AUTO_REPLY | I am out of office. | Сохранить, не увеличивать human reply и не создавать handoff |
| OBJECTION | This does not fit our budget. | Черновик для человека; цену и условия не менять |
| REFUSAL | No thank you, I am not interested. | Прекратить обращения к этому контакту данного владельца |
| STOP | STOP | Немедленно записать запрет, отменить подготовленные обращения, не снимать запрет поздним интересом |
| INTEREST | I want to discuss purchasing this demonstration. | Подготовить пакет через существующий F1-19; только в SYNTHETIC-кампании |
| UNCERTAIN | Maybe, but I cannot decide. | Ручной разбор, без передачи как заинтересованного клиента |

Категории — тестовый контракт модели. Качество настоящего классификатора потребует отдельного независимого корпуса, включая отрицания, цитаты, пересланные сообщения и prompt injection. Совпадение фрагмента текста не заменяет семантическую оценку.

## Повторы, STOP и часы

- Транзакция `BEGIN IMMEDIATE` сохраняет результат операции вместе с событием. Одинаковый event ID с тем же входом возвращает прежний результат; другой вход — конфликт. Время повторной обработки не входит в fingerprint.
- Message ID — дополнительная граница: тот же входящий текст под новым event ID не создаёт новый ответ. Тот же message ID с другим текстом отвергается как конфликт.
- Все операции используют явное aware-время. Новые команды с откатом processing clock отвергаются; повтор уже выполненной команды возвращает прежний результат. Это не реализация распределённых event-time часов.
- ID передачи включает область кампании и лида; одинаковый ID провайдерского события в разных кампаниях не сталкивает пакеты.
- STOP распространяется на нормализованный email в пределах одного `client_id`, включая другие его кампании. Он не затрагивает другого владельца. Идентификация одного человека по нескольким адресам не реализована.
- Follow-up разрешён только при `WAITING_REPLY`, наблюдённом DELIVERED и отсутствии незавершённого действия. В demo предлагаются два повторных обращения через 48/120 часов от первоначальной доставки. Эти значения не утверждены для реальной кампании.
- Синтетический ACK ожидается 60 минут от подготовки пакета, включая ожидание доставки. Это предлагаемый предельный срок стенда, не коммерческий SLA. По истечении — ручная эскалация, без нового контакта с клиентом.
- После передачи, STOP, отказа или эскалации поздние сообщения сохраняются; поздняя квитанция не возвращает лид к follow-up.
- Аварийная остановка запрещает новые обращения и отменяет подготовленные drafts. Уже наблюдённые receipts и локальные действия менеджера могут быть сохранены как результаты сверки; это не новый внешний эффект.

## Участие человека

Настоящие цены, обязательства, правовые основания, первый рынок, модель и полномочия остаются решениями владельца. Manager ACK стенда не аутентифицирован и помечен `LOCAL_UNAUTHENTICATED_FIXTURE`; до реальной эксплуатации требуется серверная проверка identity и полномочий. Ни одна демонстрационная квитанция не является доказательством отправки сообщения или работы менеджера.
