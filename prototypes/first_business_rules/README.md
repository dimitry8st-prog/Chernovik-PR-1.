# Sales Manager FIRST: рабочий скелет бизнес-правил

**OFFLINE_PROTOTYPE / SIMULATION / NO_OUTBOUND**

Дата подготовки: 31 октября 2026 года. Основание — задание Дмитрию на доработку предложения для Владимира и поручение создать работающий скелет.

Это исполняемый локальный стенд: профиль кампании, квалификация компании, отдельная проверка допуска контакта, сохранение переписки, проверка предложения AI, черновики, ограниченные follow-up, STOP, подготовка передачи через настоящие F1-09/F1-19, отдельное принятие менеджером и расчёт метрик. CLI демонстрирует полный синтетический цикл и неблагоприятные сценарии.

Профиль не содержит реальных продуктов, цен, стран или разрешений. Пример `SYNTHETIC` и незаполненный паспорт `PENDING_OWNER_INPUT` разделены. `live_ready` всегда false; реализация отправки отсутствует. Наличие идентификатора согласования в фикстуре не означает настоящее согласование.

## Запуск

Нужен Python 3.10+ со стандартными модулями `sqlite3` и `unittest`. Устанавливать пакеты не требуется. Из корня этого репозитория:

```bash
cd prototypes/first_business_rules
python -B -m unittest discover -s tests -v
python -B -m first_business check-policy config/campaign.pending.json
python -B -m first_business demo --db demo.sqlite3 --output demo-report.json
```

В Windows при необходимости используйте `py -3` вместо `python`.

Для нового демонстрационного запуска нужен новый путь к БД и отчёту. Команда не перезаписывает существующий файл. Временные БД и отчёты не включаются в git.

Повторный расчёт по сохранённому журналу:

```bash
python -B -m first_business report --db demo.sqlite3 --campaign 22222222-2222-4222-8222-222222222222 --start 2026-10-31T09:00:00Z --end 2026-11-07T09:00:00Z
```

Команда проверки полноты паспорта:

```bash
python -B -m first_business check-policy config/campaign.pending.json --require-complete
```

Для незаполненного профиля ожидается код завершения 2 и список недостающих полей. Это рабочая блокировка, а не ошибка запуска стенда. `python -m first_business live-send` при любых настройках завершается `NO_OUTBOUND_HOLD`.

## Что показывает demo

| Синтетический контакт | Проверяемое поведение |
| --- | --- |
| alpha | Доставка в симуляции, вопрос, следующий ответ с интересом, реальная сборка пакета F1-19, симуляция доставки и отдельный local fixture ACK менеджера |
| beta | STOP, последующий интерес архивируется, follow-up запрещён |
| gamma | Компания подходит профилю, но основания контакта нет; черновик заблокирован |
| delta | UNKNOWN не превращается в разрешение повторной отправки |
| epsilon | Follow-up подготавливается только после подтверждённой симуляцией доставки и наступления срока |

Повтор исходного события alpha не создаёт ещё один контакт. В отчёте есть полный журнал, история сообщений, пакеты, черновики, числители/знаменатели, расходы в `DEMO` и отдельно незаполненные параметры реальной кампании. Ни одно сообщение не отправляется.

## Границы результата

- Код помещается только в новый `prototypes/first_business_rules/`. `SOURCE/`, `project_records/` и `transfer/` не меняются. Это отдельная ветка, не внедрение CP12 и не исправление производственного task store.
- SQLite — только локальное хранилище этого стенда. Существующий PostgreSQL FIRST не заменяется; production-адаптер и миграции здесь не установлены.
- Реальный классификатор AI не подключён. Структурированное предложение задаётся фикстурой; проверяются формат, цитата, порог и разрешённые факты. Совпадение цитаты с текстом не доказывает правильность определения намерения. Узкий приоритетный фильтр явных отказов консервативен и не является универсальным NLP-классификатором.
- Истинность продуктовых фактов, наличие настоящего согласия, подлинность manager identity и юридическая допустимость не устанавливаются фикстурой. Для реальной кампании требуются доверенные серверные источники и отдельная приёмка.
- `PREPARED`, принятие провайдером, доставка и принятие человеком — разные события. Все receipts и ACK в этом стенде синтетические. Late receipt после запрета сохраняется для сверки, но не возобновляет автоматический диалог.
- При >100 сообщениях до подготовки передачи F1-09 отклоняет пакет. История сохраняется, скелет переводит случай на ручной разбор; обрезки истории нет. Сообщения после передачи продолжают сохраняться без повторной подготовки пакета.
- Нет SMTP, Make, webhooks, поиска компаний, оплачиваемых API, настоящих отправок или загрузки секретов. P19 и существующие компоненты каталога/расписания не переписываются.
- Нулевые наблюдения нарушений в отчёте не являются гарантией отсутствия нарушений. Качество AI и коммерческая эффективность этим прогоном не измерены.

Следующий этап — заполнить и утвердить паспорт реальной кампании, добавить утверждённые тексты и подключить адаптеры через действующие контракты. В этом наборе кода нет флага, который включает реальную рассылку.
